# LoveTree 4.1 리팩터링 이유와 계획 (2026-11-08)

추적 이슈: #231

## 요약
LoveTree 4.1 화면 코드를 기능 변경 없이 정리합니다. 목표는 "고칠 곳을 쉽게 찾고, 레인끼리 덜 부딪히고, 한 곳 고친 게 다른 곳을 깨뜨리지 않게" 만드는 것입니다.

## 왜 지금 하나 (리팩터링 이유)
- **고칠 곳이 흩어져 있음**: 기억책 하나를 고치려면 원본 HTML 두 벌(`views/`, `design/views/`), 주입 스크립트(`scripts/apply-book-usability.mjs`), 덮어쓰기 JS·CSS(`public/v41/book-usability.mjs` 등), 셸까지 4~5곳을 봐야 함.
- **원본이 두 벌**: 안쪽 화면 원본이 `views/`(실제 기록용)와 `design/views/`(예시·파일·공유용) 두 곳에 있음. 단순 사본이 아니라 서로 다른 변형이라(#230 조사), 기억책 개선도 두 벌에 주입하고 두 벌을 시험해야 함. 셸이 `source==='server'` 여부로 경로를 고름(`shell.mjs:214`).
- **셸이 한 파일에 몰림**: `public/v41/shell.mjs`(약 481줄, 한 줄 2,000자 넘는 곳 있음)에 화면 전환, 헤더, 로그인, 테마, 패널, 메시지가 모두 들어 있음. 11월 7~8일 작업에서 여러 레인이 이 파일에 몰려 충돌·중복이 생김.
- **압축된 원본**: 기억책(track59)·기억 보드(track58)·관계 지도(track56) 원본 HTML 안에 압축된 스크립트·스타일이 있어 사람이 읽고 고치기 어려움. 그래서 개선 내용을 원본 대신 "주입"으로 덧붙여 옴.
- **멀리 떨어진 곳이 깨짐**: 로그인 뒤 엉뚱한 화면으로 떨어진 결함(#227)처럼, 한 곳 수정이 다른 곳을 깨뜨리는 사례가 있었음.
- **지금이 적기**: 화면·동작이 막 확정됐고 시험이 480개 넘게 쌓여 있어 "전과 똑같이 동작하는지" 확인할 장치가 갖춰져 있음. 정원 테마를 기억 보드·관계 지도에 칠하는 작업도 정리 뒤가 훨씬 쉬움.

## 원칙
1. **기능·문구·디자인 변경 0.** 코드 위치와 구조만 바꿈.
2. **리팩터링 중인 파일에는 다른 기능 작업을 넣지 않음.** 섞이면 무엇이 깨뜨렸는지 알 수 없음.
3. **기준 스크린샷 비교.** 도구: `tools/visual-baseline/`(capture·compare, `--base`로 로컬 미리보기 가능). 고치기 전·후 같은 조건(로그아웃 예시 모드, 1440·390, 밤·정원)으로 찍어 차이 0 또는 차이 이유 설명.
4. **작은 PR 여러 번.** PR마다 `npm test`·build·CI 전부 pass, Pages 반영 뒤 `tools/postdeploy` 로그아웃 fail 0.
5. **이름 유지.** 함수 이름·메시지 이름(`lt41-*`)·DOM id·저장 키(`lt41.*`)는 바꾸지 않음(다른 화면·시험·postdeploy가 의존).
6. **한 작업은 한 레인에만.** 같은 파일을 두 레인에 주지 않음.
