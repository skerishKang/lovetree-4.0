## 2. 데이터 규칙 (꼬리표 → 점·선)

### 점
- **허브(큰 점)**: 확정 꼬리표 값 중 종류가 **가수·노래·무대**인 것. 같은 값을 가진 순간이 **2개 이상**일 때만 허브가 된다. 1개뿐이면 허브를 만들지 않고 순간의 꼬리표 칩으로만 보인다(희귀 값이 지도를 채우는 일을 막는다).
- **순간(작은 점)**: 모든 순간. 꼬리표가 없어도 점이 된다(아래 '꼬리표 없는 순간').
- **멤버·활동기·감정은 1차 허브가 아니다.** 상세 판 칩과 걸러 보기(후속 PR)로 쓴다. 확장은 `TAG_KINDS`에 한 줄만 더하면 되도록 종류 목록을 코드에서 하드코딩하지 않는다.

### 묶음 소속 (순간 하나는 하나의 묶음에만 살고, 선은 여러 허브로)
1. 1차 소속은 **무대 > 노래 > 가수** 순으로 첫 꼬리표를 고른다. 이유: 팬의 기억 단위는 '그 무대에서 본 것'(언제·어디서)이고, 무대가 없으면 노래(무엇), 그것도 없으면 가수(누구)가 남는다.
2. 소속 선은 **1차 허브 → 순간 점**의 짧은 실만 그린다. 1차가 아닌 꼬리표는 상세 판의 칩으로 확인한다(모든 허브에 선을 그리면 가수 하나가 순간 대부분을 잡아 선이 바닥을 채운다).
3. 다만 1차 소속이 하나도 없는 허브(예: 가수:RESCENE — 다른 가수 직캠 2개에만 붙음)는 **점선**으로 관련 순간과 이어 고아 허브로 두지 않는다. 발자취 줄과 색·굵기가 달라 섞여 보이지 않게 한다.

### 선
- **발자취 줄(핵심)**: 전체 순간을 **시간 순서**(무대 날짜, #627 0단계; 같은 날은 만든 순서)로 잇는 한 줄. 클러스터 사이를 가로지르는 게 의도다 — '덩어리로 모인 기록을 시간으로 다시 걷는' 경험. 중요 표시(★) 순간은 줄 위에서 점이 커진다.
- **직접 이은 줄(next/branch)**: 1차 화면에서는 숨기고 상세 판의 '이전·다음 순간'으로 보여 준다. 지도의 parent 선 개념과 섞이면 두 재료가 지워지기 때문. 후속 PR에서 토글로 검토한다.
- **발자취 재생**: 시간 순서대로 점을 밝히며 줄을 따라 걷는 애니메이션(현재 지도의 재생은 예시 데이터만 허용됐다 — 그래프 보기는 실제 기록에서도 시간 순서 재생이 가능하다. 이것이 '지도 발자취 수리를 2단계에 합친다'는 대표 결정의 실체다).

### 꼬리표 없는 순간
- 허브 묶음에 넣지 않고 무대 한쪽의 **'꼬리표 없는' 선반**에 시간 순서로 흐리게 놓는다. 발자취 줄은 이 점도 지난다.
- 선반 안내에 '꼬리표 한 번에 제안받기' 버튼 자리를 둔다 — #680에서 만든 기능(꼬리표 정리 화면)과 연결. 0개면 선반 자체가 없다.
- 지도가 '꼬리표를 채우라는 부드러운 부탁'을 하게 하는 장치다. 숨기지 않고(상태를 숨기지 않는다) 구분해서 보여 준다.

### 순간 1개 · 10개 · 100개
| 순간 수 | 허브 | 무대 모양 |
| --- | --- | --- |
| 1개 | 없음 | 점 하나가 무대 중앙. 안내 문구 "순간이 하나예요. 다음 순간을 남기면 흐름이 보여요." 발자취 줄 없음 |
| 10개 | 0~4개 | 같은 규칙 그대로. 허블 최소 크기와 묶음 반지름 최소값이 10개일 때의 모양을 정한다. 발자취는 10개 점을 잇는 한 줄 |
| 100개 | 9~15개쯤 | **허브 라벨은 묶음 크기 상위 12개만** 화면에, 나머지는 범례에서 이름으로. 순간 점 라벨은 항상 숨김(선택 시 상세 판). 묶음 반지름은 개수의 제곱근에 비례해 축소 |

## 4. 화면 구성 (390 · 1440)

공통: 검은 무대 위 금테 카드 프레임(shell.css의 iframe 프레임과 같은 시각 언어). 색·모서리는 `identity.css`의 `--lt-*` 토큰만. 묶음 색은 종류별 토큰(무대=`--lt-gold-deep`, 노래=`--lt-rose`, 가수=`--lt-blue`)으로 범례와 지도가 바로 맞아 보이게 하고, 새 종류가 허브가 되면 `--lt-group-1..6`을 순환해 붙인다(현재 지도의 `--lt-map-group-*`는 network.css 전용 값이라 재사용하지 않는다). 글자 `undefined`·`null`·`NaN` 금지는 화면 검사기 단정으로 지킨다.

- **1440**: 왼쪽 그래프 무대(정사각형에 가까운 영역), 오른쪽 레일(약 340px) = 범례(허브 목록·개수·종류) + 선택한 순간/허브 상세 + 발자취 재생 버튼. 위쪽에 '발자취 지도 / 그래프 보기' 전환 알약(지도와 같은 입구에서 두 보기).
- **390**: 위 그래프 무대(높이 약 58dvh, 가로 꽉 참) + 아래 상세 시트(선택 시 슬라이드업). 범례는 상단 알약 안에 접어 두고, 조작 줄은 하단 고정 높이 한 줄 — #679/#681의 지도 390 조작 줄 잘림 패턴(가로 스크롤·높이 초과)을 반복하지 않게 iframe 안 독립 높이로 만든다.
- 상세 판: 제목·무대 날짜·감정·꼬리표 칩(확정 모양)·메모·'이전 · 다음 순간'(발자취 이웃). 허브 선택 시 묶음 순간 목록.

## 5. 지금 지도(views/network)와의 관계 — 대체가 아니라 '보기 방식 하나로 추가'

- 지도 입구(트리 ▾ 지도) 안에 **'발자취 지도 / 그래프 보기' 전환 알약**을 둔다. 지금 지도는 parent 선(직접 이은 줄) 중심, 그래프 보기는 꼬리표 중심 — 재료가 다른 두 보기다. 서로를 지우지 않고 한 화면 안에서 고르게 한다.
- 지금 지도 파일(`views/network/**`)은 건드리지 않는다. 그래프 보기는 새 `views/graph/`(예: track HTML + graph-model.mjs + graph.js + graph.css)로 만들고 지도와 같은 runtime 데이터 읽는 방식(`parent.LT41.tree` → 순간 배열)을 따른다.
- 지도의 발자취 수리(첫 순간 경로 강조·예시 전용 재생)는 별도로 하지 않는다(대표 결정). 그래프 보기가 시간 순서 발자취·재생을 실제 기록까지로 넓혀 이 역할을 이어받는다.

## 6. 성능 한계

- 그리기는 **canvas 2D**(현재 지도와 같은 방식). 100순간 + 허브 15 = 점 115개 + 소속 선/발자취 선 약 400줄 수준 — canvas 2D로 프레임 여유.
- 라벨은 허브 상위 12개만(묶음 크기 순). 순간 점 라벨은 항상 숨김 → 라벨 겹침 계산량이 허브 수에만 비례.
- **300순간을 넘기면 묶음을 접는다**: 허브 점 + 'n개' 숫자만 남기고 순간 점은 눌러 펼친다. 펼친 묶음은 1화면에 최대 2~3개 제한.
- 재생은 requestAnimationFrame 1루프, 점 밝히기만(점을 옮기지 않는다). 모바일 390도 같은 한도를 쓴다.
