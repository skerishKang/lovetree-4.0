## 2. 데이터 규칙 (꼬리표 → 점·선)

### 점
- **허브(큰 점)**: 방향 문서 기준 **노래·멤버·무대**. 확정 꼬리표 값 중 같은 값을 가진 순간이 **2개 이상**일 때만 허브가 된다. 1개뿐이면 허브를 만들지 않고 순간의 꼬리표 칩으로만 보인다(희귀 값이 지도를 채우는 일을 막는다).
- **가수도 같은 방식의 허브가 되되 한 단계 작은 점** — 묶음 장소가 없는 가수-만 순간(프로필·포토)을 두기 위해. 4.1 꼬리표 종류에 가수가 추가된(#684) 것을 반영한 것이고, 큰 점의 축은 방향 문서대로 노래·멤버·무대다.
- **순간(큰 점, 썸네일)**: 모든 순간이 허브 주위 **고리** 위에 앉는다. 이미지가 있으면 썸네일 동그라미(예시 이미지 축소판), 없으면 묶음 색 점. 중요 표시 순간은 금테 링. '노래 하나 = 순간 한 덩어리'가 한눈에 보이는 것이 1차 목표다.
- **활동기·감정은 허브가 아니다.** 상세 판 칩과 걸러 보기(후속 PR)로 쓴다. 확장은 종류 목록에 한 줄만 더하면 되도록 코드에서 하드코딩하지 않는다.

### 묶음 소속 (순간 하나는 하나의 묶음에만 살고, 고리는 하나)
1. 1차 소속은 **무대 > 노래 > 멤버 > 가수** 순으로 첫 꼬리표를 고른다. 이유: 팬의 기억 단위는 '그 무대에서 본 것'(언제·어디서)이고, 무대가 없으면 노래(무엇), 멤버(누구), 가수 순으로 남는다.
2. 1차 소속이 하나도 없는 허브(예: 가수:RESCENE — 다른 가수 직캠 2개에만 붙음)는 **점선**으로 관련 순간과 이어 고아 허브로 두지 않는다.
3. 고리 위의 점 순서 = **그 묶음 안의 시간 순서**(시계 방향). 고리가 곧 묶음의 작은 시간줄이 된다.

### 선 — 발자취 줄은 '고를 때만' (대표 결정 2026-11-15)
- **기본 화면에는 발자취 줄을 그리지 않는다.** 40순간을 시간 순서로 한 줄로 잇으면 화면 전체를 가로지르는 실뭉치가 되고, 이는 지금 지도의 '흩어져 보임'과 같은 문제다.
- 대신 시간 흐름은 두 곳에서 읽는다: (a) 고리 위 점들이 시간 순서로 앉아 있다, (b) 순간·묶음을 고르거나 '발자취 걷기'를 눌렀을 때 **그 길만 밝게** 그린다 — 고른 순간은 앞뒤 이음(발자취 이전·다음), 고른 묶음은 그 묶음의 시간 흐름, 걷기는 시간 순서 전체를 한 점씩 밝히며 걷는다.
- '처음'·'지금' 표시도 길이 보일 때만, 길 위의 점 옆에 붙인다.
- **직접 이은 줄(next/branch)**: 상세 판의 '이전·다음 순간'과 후속 PR의 토글로 검토한다(지도의 parent 선 개념과 섞이면 두 재료가 지워진다).
- 발자취 재생은 실제 기록에서도 시간 순서로 가능하다 — 현재 지도의 재생은 예시 데이터만 허용됐고, '지도 발자취 수리를 2단계에 합친다'는 대표 결정의 실체다.

### 꼬리표 없는 순간
- 허브 묶음에 넣지 않고 무대 아래 **'꼬리표 없는' 선반**에 시간 순서로 흐리게 놓는다. 걷기 길은 이 점도 지난다.
- 선반 안내에 '꼬리표 한 번에 제안받기' 버튼 자리 — #680에서 만든 기능(꼬리표 정리 화면)과 연결. 0개면 선반 자체가 없다.
- 지도가 '꼬리표를 채우라는 부드러운 부탁'을 하게 하는 장치다. 숨기지 않고(상태를 숨기지 않는다) 구분해서 보여 준다.

### 순간 1개 · 10개 · 100개
| 순간 수 | 허브 | 무대 모양 |
| --- | --- | --- |
| 1개 | 없음 | 점 하나가 무대 중앙. 안내 문구 "순간이 하나예요. 다음 순간을 남기면 흐름이 보여요." |
| 10개 | 0~4개 | 같은 규칙 그대로. 고리 최소 반지름은 허브 점 바로 밖. 발자취 걷기는 10개 점을 잇는 한 줄 |

## 4. 화면 구성 (390 · 1440)

공통: 검은 무대 위 금테 카드 프레임(shell.css의 iframe 프레임과 같은 시각 언어). 색·모서리는 `identity.css`의 `--lt-*` 토큰만. 묶음 색은 종류별 토큰(무대=`--lt-gold-deep`, 노래=`--lt-rose`, 멤버=`--lt-violet`, 가수=`--lt-blue`). 글자 `undefined`·`null`·`NaN` 금지와 가로 넘침 0은 수치로 확인한다.

- **1440**: 왼쪽 그래프 무대, 오른쪽 레일(약 340px) = 범례(묶음 목록·개수·종류) + 선택한 순간/허브 상세 + 발자취 걷기 버튼. 위쪽에 '발자취 지도 / 그래프 보기' 전환 알약(지도와 같은 입구에서 두 보기).
- **허브를 누르면** 상세 판에 **'이 노래의 내 순간들'(묶음 종류별 문구)이 시간 순서 목록으로 바로 뜬다** — 3단계 '다른 팬 보기', 4단계 '새것 추천'이 이 목록 아래에 붙는 자리다.
- **390**: 위 그래프 무대(가로 꽉 참) + 아래 상세 시트. 범례는 2열로 접고, 머리 줄은 줄바꿈으로 가로 넘침 0을 유지한다. 조작 줄은 하단 고정 높이 한 줄(#679/#681의 지도 390 조작 줄 잘림 패턴을 반복하지 않게 iframe 안 독립 높이).
- 상세 판: 제목·무대 날짜·감정·꼬리표 칩(확정 모양)·메모·'이전 · 다음 순간'(발자취 이웃, 시간 순서).

## 5. 지금 지도(views/network)와의 관계 — 대체가 아니라 '보기 방식 하나로 추가'

- 지도 입구(트리 ▾ 지도) 안에 **'발자취 지도 / 그래프 보기' 전환 알약**을 둔다. PR3(2026-11-15)에서는 화면만 만들고 메뉴에 붙이지 않았다 — 주소로만 열린다(#my/graph). 붙일 자리는 지도의 '그물형·동심원형' 보기 종류 옆(같은 view-switch 알약 안)이다. 지금 지도는 parent 선(직접 이은 줄) 중심, 그래프 보기는 꼬리표 중심 — 재료가 다른 두 보기다. 서로를 지우지 않고 한 화면 안에서 고르게 한다.
- 지금 지도 파일(`views/network/**`)은 건드리지 않는다. 그래프 보기는 새 `views/graph/`(예: track HTML + graph-model.mjs + graph.js + graph.css)로 만들고 지도와 같은 runtime 데이터 읽는 방식(`parent.LT41.tree` → 순간 배열)을 따른다.
- 지도의 발자취 수리(첫 순간 경로 강조·예시 전용 재생)는 별도로 하지 않는다(대표 결정). 그래프 보기가 시간 순서 발자취·재생을 실제 기록까지로 넓혀 이 역할을 이어받는다.

## 6. 성능 한계

- 그리기는 **canvas 2D**(현재 지도와 같은 방식). 100순간 + 허브 15 = 점 115개 + 고리/선 수백 줄 — canvas 2D로 프레임 여유. (시안은 SVG로 그렸다 — 배치·규칙을 눈으로 확인하는 물건이고, 실제 화면은 canvas로 옮긴다.)
- 허브 이름은 묶음 크기 상위 12개만. 순간 점 라벨은 항상 숨김 → 이름 겹침 계산이 허브 수에만 비례.
- **300순간을 넘기면 묶음을 접는다**: 허브 점 + 'n개' 숫자만 남기고 눌러 펼친다. 펼친 묶음은 1화면에 최대 2~3개 제한.
- 재생은 requestAnimationFrame 1루프, 점 밝히기만(점을 옮기지 않는다). 모바일 390도 같은 한도.
