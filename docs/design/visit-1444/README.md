## 1. 들어가는 곳

| 입구 | 지금 | 방문하기 뒤 | 첫 화면 |
|---|---|---|---|
| 둘러보기 트리 카드 | '공개 순간 미리보기' 창(`community-panel.mjs` renderPreview) | 누르면 바로 방문 `#visit/<id>` | 주인이 트리 관리에서 고른 '이 트리를 열 때 처음 보일 화면'(openView, #1367). 없거나 모르는 값이면 트리 보기. 그 위에 명판 |
| 순간 보기 오른쪽 줄의 '트리' 단추 | 그 트리를 책으로(`#share/<id>/book`) | `#visit/<id>/tree?moment=<순간>` | 트리 보기, 뿌리에서 그 순간까지 길에 불이 켜지고 방문 판이 열린 채 — "이 순간이 그 사람 트리의 어디에 있나"가 핵심이라 openView를 따르지 않는다 |
| 순간 카드 왼쪽 위 트리 이름 메뉴 | '이 트리 순간만 보기' 하나 | 같은 메뉴에 '이 러브트리 방문하기'를 더한다(두 항목) | 위와 같음 |
| 사람 이름 | 카드에 이름은 AI 명예회원만 보임 | AI 명예회원 이름(나중에 공개 별명)을 누르면 `#visit/<id>/shelf` | 그 사람의 서재 |
| 공유 링크 `#share/<id>/<보기>`, `/t/<id>` | 공유 방문자 보기(셸 source `share`) | 같은 방문 모드. 들어온 뒤 주소를 `#visit/...`로 바꿔 적는다(replace). 옛 링크는 계속 열린다 | 링크에 적힌 보기(공유한 사람이 고른 것)와 시작 순간(entryMomentId). 보기가 없으면 openView |

**주소 규칙**
- `#visit/<공유 아이디>` → 그 트리의 openView
- `#visit/<공유 아이디>/<tree|board|book|map|shelf>` + 선택 `?moment=<순간 id>`
- 공유 아이디는 트리 하나의 공개 손잡이로 이미 있다(20~64자 무작위). #1443 예시의 `#u/<공개 아이디>`처럼 **사람 아이디를 새로 만들지 않는다** — 서재는 서버가 '이 공유 트리의 주인'을 찾아 묶는다. (대표 결정 2번)
- 새로고침·주소 복사·뒤로·앞으로 모두 같은 방문 화면. 방문 안의 화면 이동은 기록 한 칸씩, 방문 첫 화면에서 뒤로 한 번 더면 들어오기 전 화면.
- 지금 코드에서 본 틈: 공유 방문 중 '트리' 탭으로 가면 주소가 `#tree`로 바뀌어(`shell/location.mjs` writeLocation이 공유 주소를 책·보드·지도에서만 남김) 새로고침하면 방문이 풀린다. 방문 주소는 다섯 보기(+서재) 모두 남긴다.

**들어가는 순간**: 그 사람의 트리가 화면 가득(전체 맞춤)이고, 넓은 화면은 왼쪽 아래, 휴대폰은 아래 판으로 **명판**(트리 이름·주제·주인 표시·순간 수·갈래 수·고친 날·[뿌리부터 이어 보기]·[서재 · 공개 트리 n])이 뜬다. 첫 동작(순간 누르기·끌기·확대·보기 바꾸기)에서 명판은 접혀 도구 줄의 트리 이름 단추로 들어간다. 같은 방문 안에서는 다시 뜨지 않는다(메모리만, 기기 저장 없음).

## 2. 방문 중 화면

### 머리줄·방문 띠·도구 줄

| 줄 | 내 화면 | 방문 중 |
|---|---|---|
| 머리줄(64px, 390은 56px) | `LoveTree │ 둘러보기 │ 서재 · 트리 · 보드 · 책 · 지도 │ ☀ │ ＋ 순간 추가 │ 나` | `LoveTree │ 둘러보기 │ 서재 · 트리 · 보드 · 책 · 지도 │ ☀ │ 나(또는 로그인)` — 순간 추가·휴대폰 떠 있는 ＋는 자리째 없다(#1447 구멍 없음 규칙). 탭 자리·높이는 그대로라 손이 기억하는 자리가 같다 |
| 방문 띠(44px, 새로) | 없음 | `[방문 중] 한 팬의 러브트리 · 공개 트리 3개 · 지금 '트리 이름'        [나가기]` |
| 도구 줄(56px, 390은 52px) | 맨 왼쪽 내 트리 고르기(금색 채움) | 맨 왼쪽 **이 러브트리의 트리 단추**(테두리만 — 금색 채움은 '내 트리' 전용) + 순간 수·고친 날. 오른쪽은 화면별 보기 도구, 구분선 뒤 이 트리의 ♡·댓글·공유·⋯ |

- 방문 띠의 이름: 지금 원칙(이름·아이디·이메일 비공개) 때문에 기본은 **'한 팬의 러브트리'**. AI 명예회원은 지금 카드처럼 'AI 명예회원 ○○의 러브트리'. 주인이 켜는 '공개 별명'은 대표 결정 1번(캡처 두 안).
- 띠 뒤 작은 글씨: 주인이 올린 사진이 빠졌으면 '· 사진 2장은 주인만 볼 수 있어요', AI 명예회원이면 'AI 명예회원이 만든 트리예요'(#1462 지적: 지금은 이 두 안내가 화면 어디에도 안 보인다).
- 팔로우(#1426) 자리: 띠 오른쪽 [나가기] 왼쪽에 비워 둔다(이번엔 안 만든다).
- [나가기]: 들어오기 전 자리로 — 둘러보기에서 왔으면 그 카드에 초점(금테 + '방금 방문'), 공유 링크로 바로 왔으면 첫 화면. 나간 뒤 알림: "'트리 이름' 방문을 마쳤어요. 내 화면과 설정은 그대로예요. [다시 방문]".
- 휴대폰(390): 머리줄은 `LT · ☀ · 나 · ☰`(보기 탭은 지금처럼 ☰ 안), 방문 띠는 '방문 중 + 이름 + 나가기'만, 도구 줄은 트리 단추·이어 보기·전체·♡·⋯.

## 3. 읽기 전용 — 막는 것과 허용하는 것

**신호 하나**: 셸의 기록 출처(source)에 `visit`을 두고(지금 `share` 자리를 대신), 프레임에는 `LT41.readOnly = true` 한 값만 넘긴다. 막는 곳은 네 겹이지만 판단은 모두 이 하나를 본다.
1. **셸 메시지 관문**(`shell/messages.mjs` 첫 줄): 방문 중에는 허용 목록 메시지만 받는다 — 순간 고르기(selection·select), 화면 이동(navigate·openBook·openView·openNetwork), 주소 기록(boardDetail·choose), 크게 보기(viewer·momentsOpened), 테마, 둘러보기·로그인·계정. 그 밖(boardSync·tags·storySave·write·newTree·move·moveMoments·manageTree·cleanup·prefs·journeySave·mediaMetadata·boardTheme 등)은 버리고 시험이 센다. 지금은 메시지마다 `getSource() !== 'server'`를 따로 본다(빠진 곳이 생기기 쉽다).
2. **쓰기 함수 잠금**: 방문 중에는 내 기록 연결(member)을 멈춘다(지금 공유 보기의 `pauseMember()` 그대로). 저장 예약·붙여넣기 담기(`quick-intake.mjs`)·끌어 놓기 추가(`shell/quick-add.mjs`)·단축키 입구가 이 상태를 보고 아무것도 하지 않는다.
3. **화면 readOnly**: `runtime.js`의 한 판정(지금 `share`·예시)에 `visit`을 더한다. 이미 `LTDEMO.readOnly`를 보는 보드·책·썸네일 고치기 입구가 그대로 막힌다.
4. **서버**: 6번의 방문 표식 거부 + 원래 있는 주인 확인.

**기기 저장 끄기**: 셸과 화면이 쓰는 저장소 접근을 한 덮개(방문 중에는 메모리 저장소)로 바꾼다. `lovetree.v41.*`(작업 공간 저장본·최근 위치·대기 쓰기)와 `lt41.*`(보드 배치·보기 설정·안내 봤음 등)를 방문 중에는 읽지도 쓰지도 않는다. 나가면 덮개를 걷고 내 기록을 다시 연다(서버본이 이긴다). 예외는 대표 결정 5번(테마) 하나만.

**서재 규칙(가장 중요한 안전 조건)**
- 지금 서버는 순간이 있는 모든 트리에 자동 공유 줄을 만들고(#538, origin `auto`) 공개가 기본값이라 **링크를 아는 사람은 볼 수 있다**. 둘러보기 소개는 기본 꺼짐이다(#1495).
- 그래서 서재에 '같은 주인의 공개 트리 전부'를 내리면 링크로만 준 트리가 다른 방문자에게 드러난다.
- → 서재 = **둘러보기에 소개한 트리**(소개 켜짐) ∩ 공개 ∩ 공유 살아 있음. 둘러보기 목록과 같은 거름 함수를 쓴다.
- → **링크로만 공개한 트리로 들어오면 서재에는 그 트리 하나만** 보인다(그 주인의 다른 트리와 이어 주지 않는다).

**마음 한마디**: 지금은 공개 트리의 마음 한마디가 모두 공개다(책에 보임). 순간별 숨기기는 데이터에 없다 → #1443 2차 '보기별 숨기기'와 함께 다룬다.

**손님(로그아웃)** — 제안: 방문 허용.
- 볼 수 있음: 트리·보드·책·지도·서재·재생·이어 보기·댓글 읽기·공유 링크 복사.
- 못 함: ♡·댓글 쓰기·담기·신고 → 누르면 그 자리에 로그인 안내("마음·댓글·담기는 로그인하면 할 수 있어요"), 로그인 뒤 같은 방문 주소로 돌아온다.
- 근거: 공유 링크 손님 보기(#1236)가 이미 로그아웃 감상을 허용하고, 공개 읽기·댓글 읽기 API가 로그인 없이 열려 있다.

**숨긴 공개자**: 내가 '이 공개자의 트리 숨기기'를 한 주인은 둘러보기에서 안 보이고, 링크로 들어오면 보기는 되지만 ♡·댓글은 지금처럼 서버가 막는다(reaction_blocked).

**이미 있는 것**

| 경로 | 쓰임 | 방문에서 |

| `GET /api/public/shares/:id` | 공유 트리 1개(비공개면 403, 취소 410, 순간 0이면 422, 올린 사진 빈 주소, copiedFrom 뺌, AI 표시) | 공유 링크 입구·`/t/`에 남김. 방문 화면은 아래 새 경로로 |

**새로 필요한 것**

① **방문 데이터** `GET /api/public/visits/:공유 아이디`
```json
{
  "visit": { "shareId": "…", "view": "tree", "entryMomentId": "…", "momentCount": 24,
             "updatedAt": "…", "aiTester": false, "ownerLabel": "", "omittedPrivateMedia": 0 },
  "tree":  { "title": "…", "subject": "…", "openView": "tree", "coverMomentId": "…", "coverMode": "design",
             "coverDesign": "…", "createdAt": "…", "updatedAt": "…",
             "moments": [ { "id": "…", "parentId": null, "title": "…", "note": "…", "emotion": "…", "date": "…",
                            "url": "…", "mediaMetadata": {}, "startSeconds": 0, "endSeconds": null,
                            "relation": "…", "links": [], "x": 0, "y": 0, "rot": 0, "pinStyle": "…",
                            "cardStyle": "…", "color": "…", "keywords": [], "createdAt": "…" } ] },
  "shelf": [ { "shareId": "…", "title": "…", "subject": "…", "momentCount": 12, "updatedAt": "…",
               "openView": "book", "cover": { "type": "youtube", "thumbnailUrl": "…" } } ],
  "stats": { "hearts": 12, "comments": 3, "mine": [] }
}
```
- 투영은 **허용 목록**(칸을 골라 담기)으로 한다. 지금 공유 읽기는 트리를 통째로 펼친 뒤 빼는 방식(`...source`, copiedFrom 삭제)이라 앞으로 트리에 생길 새 칸이 그대로 나갈 수 있다. 주인 쪽 내부 트리 아이디도 내리지 않고 공유 아이디만 손잡이로 쓴다.
- ownerLabel은 AI 명예회원만 공개 이름, 그 밖은 빈 값(화면은 '한 팬').

② **담기** `POST /api/visits/:공유 아이디/keep` `{momentIds[], treeIds[], force}` + 요청 키
- 서버가 공개 투영에서 순간을 **다시 읽어** 내 문서에 사본을 붙인다(화면이 보낸 내용을 믿지 않음 — 비공개 사진·링크 전용 트리의 순간은 처음부터 고를 수 없다).
- 사본 표시는 지금 담기(`moments-copy.mjs`)와 같은 '원래 출처' 한 줄. 저장 번호를 맞추고 충돌이면 한 번 다시 한다.
- 응답 `{kept:[{treeId, momentId}], already:[treeId]}`. force 없이 '이미 있음'이면 409와 그 트리 목록 → 화면이 "이 트리에 같은 영상이 이미 있어요 · 그래도 넣기 / 건너뛰기"를 묻는다.
- `GET /api/visits/:공유 아이디/keep-targets?moment=<id>` → 내 트리 목록(이름·순간 수)과 '이미 있음' 표시(#876·#1439 규칙: 영상 아이디+시작 초+끝 초 / 같은 사진 / 같은 원본).
- 대안(화면에서 담기): 방문 중에도 내 기록을 뒤에 살려 두고 지금 onAddToTree로 담는다. 서버 새 경로는 없지만, 방문 중 내 문서와 남의 트리가 같은 메모리에 있게 되어 '섞이지 않음'을 지키기 어렵다 → **서버 담기 추천**(대표 결정 9번).

③ **방문자 쓰기 거부(이중 잠금)**
- 방문 중 화면은 모든 `/api` 요청에 방문 표식 머리(`x-lt-visit: <공유 아이디>`)를 붙인다.
- 서버는 이 머리가 붙은 쓰기 — 작업 공간 저장(PUT), 공유 만들기·거두기, 트리 공개·소개 바꾸기, 사진 올리기 — 를 409 `visit_read_only`로 거절한다. 커뮤니티(♡·댓글·즐겨찾기·신고·숨기기)와 ②만 통과.
- 원래 있는 주인 확인은 그대로: 남의 트리·공유는 처음부터 못 바꾼다(`ownTree`·`share_forbidden`).
- 지금 코드에서 본 틈: 작업 공간 저장은 '보낸 사람의 문서'에 쓴다. 남의 트리가 내 기록 자리에 실린 채 저장이 돌면 내 계정에 저장될 수 있다(저장 번호 0인 새 계정은 충돌 없이 통과). 지금 공유 보기는 `pauseMember()`로 저장을 멈춰 막고 있다 → 방문 모드도 같은 방식 + 위 머리 거부로 이중.

④ 프록시 허용 목록(`functions/_lib/proxy.js`)에 새 경로 3개와 `tests/pages-proxy.test.mjs`.

**캐시·성능**
- 요청 한 번에 주인 문서 1번 읽기(지금 공유 읽기와 같음). 서재도 같은 문서 안이라 추가 문서 읽기 없음. 공유 줄·공개 상태·소개 줄은 작은 표 조회 3번.
- 응답 머리 `private, no-cache` + ETag(문서 저장 번호 + 공유·공개·소개 상태) → 새로고침은 304. **공용 캐시(CDN)에는 두지 않는다** — 주인이 비공개로 바꾸거나 공유를 거두면 다음 요청부터 바로 막혀야 한다.
- 화면은 방문 한 번 동안 메모리에만 둔다(보기 바꾸기·서재↔트리 왕복에 다시 부르지 않음, 60초 지나면 ETag로 확인). 기기 저장 없음.
- 크기: 순간 120개 트리에 약 60~100KB(압축 15KB 안팎), 지금 공유 읽기와 같은 범위. 서재는 24권까지(넘으면 더 보기).

**남의 비공개가 새지 않는 근거**
1. 서버가 고른다 — 비공개 트리는 공개 읽기에서 막히고(#538), 서재는 소개+공개+살아 있는 공유만, 순간 칸은 허용 목록, 올린 사진은 빈 주소.
2. 화면이 숨기는 것에 기대지 않는다 — 응답에 없으면 화면이 실수해도 보여 줄 수 없다.
3. 시험으로 묶는다 — 응답 JSON 전체를 훑어 `subject`·`email`·`displayName`·`accentColor`·`copiedFrom`·`/api/media/` 0개, 비공개 트리 제목 0개, 링크 전용 트리 공유 아이디 0개.
4. 쓰기는 화면(저장 호출 0)·서버(방문 표식 거부)·주인 확인 세 겹.

| 6 | G 공유 주소 합치기 정리 | `#share`·`/t/` → 방문 모드 한 길, showPublicRoute·publicProblem·visitorIntro·`#lt-visitor-caption`·header-state `share` 정리 | #1236·#1297·#1462 시험을 방문 모드로 옮김, 취소·없음·비공개 안내, 옛 링크 열림 |

- 모든 단계: 시험 계정만(방문하는 쪽·받는 쪽 둘 다), 기존 시험 기준·대기 시간은 낮추지 않는다. 방문은 새 화면이므로 시험 파일은 `tests/v41-visit.test.mjs` 하나로 모으고, 보기별 단정은 그 보기의 기존 시험 파일에 더한다.
- A·B는 화면 변화가 없어 먼저 병합해도 사용자에게 보이는 것이 없다. C를 병합하면 공유 링크 방문이 새 방문 모드로 바뀐다(보기 기능은 같고 띠·명판이 생김).
