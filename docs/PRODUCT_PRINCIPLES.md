# 러브트리 제품 원칙 — 4.1

4.1에서 실제로 내린 결정들을 한 장으로 묶은 원칙 문서다. 새 기능·화면·문구를 판단할 때
`docs/PRODUCT.md`(방향·체크리스트 전문)와 이 문서를 함께 본다. 옛 세대(LoveBud·리모네)의
문구를 베끼지 않았고, 4.1에서 실제로 그렇게 정한 근거를 이슈 번호로 붙였다.

## 러브트리가 무엇인가

러브트리는 팬이 누군가·무언가를 처음 발견하고 빠져드는 경로에서, **마음이 움직인 순간**을
주소와 구간과 메모로 남기고, 그 순간들을 **다음 순간으로 이어진 감정의 이유**로 연결해 하나의
나무로 감상하고 공유하게 하는 기록 도구다. 영상을 내려받거나 목록으로 쌓아 두는 서비스가
아니라, 사랑에 빠진 과정과 그때의 마음을 되살리는 장치다. 그래서 화면의 첫 질문은 언제나
"무엇이 몇 개 있는가"가 아니라 "무엇이 먼저 느껴져야 하는가"다.

## 원칙

1. **순간이 기본 단위다.** 영상도 게시물도 아니고, 감정이 붙은 기억의 입구인 순간을 저장한다.
   영상은 복사하지 않는다 — 어디부터 어디까지 재생할지라는 지시와 메모만 남긴다.
   → #792: 책에서 순간들을 이어 보는 재생 화면. "유튜브는 영상을 저장한다. 러브트리는 마음이
   움직인 순간을 저장한다"가 대표 방향으로 확정됐고, 시작·끝 시간으로 '가장 중요한 순간'을
   정하는 장치를 만들기로 했다.

2. **연결은 순서가 아니라 감정의 이유다.** 순간 사이의 이음선은 "다음 영상"이 아니라
   "왜 이 순간 다음에 저 순간으로 갔는가"에 답해야 한다.
   → #864: 지도 그래프에서 순간 사이 이어진 길을 발자취로 보여 주도록 다듬었다. 연결이
   감정의 흐름으로 읽히는지가 지도의 판정 기준이었다.

3. **지금 남기고 싶은 순간에서 시작한다.** 첫 기록이 최초 입덕일일 필요가 없다. 기억을
   거슬러 완벽하게 채우라고 요구하지 않는다.
   → #549: 기록이 0개인 새 계정의 첫 안내를 '불러왔어요' 대신 '반가워요. 첫 순간을 남겨
   보세요.'로 정했다. 빈 상태에서도 기록의 입구가 첫 순간을 가리킨다.

4. **사용자를 막지 말고 알려 준다.** 같은 일을 다시 하는 것이 정당한 경우가 많다. 화면이
   판단을 대신하지 않는다.
   → #876: 같은 영상을 다시 담을 때 막지 않고 담기 전에 한 번 알려 주기로 했다. 순간은
   영상이 아니라 '그 장면과 마음'이라 같은 영상을 다시 담을 이유가 있다.

5. **알림은 해야 할 일이 있을 때만 띄운다.** 잘 된 일을 자랑하는 알림은 소음이다. 실패·
   오프라인·충돌처럼 사용자가 손을 써야 할 때만 말한다.
   → #905: 자동 저장 성공 알림('서버에 저장됐어요.')을 모두 거뒀다. 배치 옮기기·꼬리표·
   마음·트리 이름 등 자동 저장은 조용히 저장되고, 저장 실패·오프라인·다른 기기 충돌만 알린다.

6. **공개는 명시적으로 한다.** 기록의 주인은 사용자다. 아무도 보지 못한 것이 기본이고,
   소유자가 확인하고 공개한 것만 다른 사람에게 보인다.
   → #425: 공개 범위를 명시적으로 정했다. 사진·개인 미디어 주소 같은 사적 정보는 표지
   모드가 '순간에서'일 때만 나간다. 공개가 기본값이었던 옛 세대 규칙은 가져오지 않았다.

## 새 기능 판단 체크리스트

1. 이 기능이 마음이 움직인 순간을 남기거나 다시 감상하게 하는가? (영상 목록 관리가 아니라)
2. 저장하는 것은 주소·구간·메모인가? 영상 파일을 복사하거나 잘라 저장하지 않는가?
3. 순간 사이의 연결과 화면의 흐름이 감정의 이유로 읽히는가?
4. 사용자를 막는 대신 알려 주는가? 막아야 한다면 그 판단이 순간의 성질에 근거하는가?
5. 공개는 명시적인가, 데이터의 주인은 사용자인가, 기존 저장 계약(계정 격리·소유권)을 지키는가?

## 하지 않는 것

- **성공 알림 남발.** 자동 저장이 성공할 때마다 토스트를 띄우지 않는다(#905). '저장했어요'
  알림이 쌓이면 정작 실패 알림이 묻힌다.
- **사용자 막기로 안전하기.** 같은 영상 다시 담기처럼 정당한 반복을 유효성 검사로 차단하지
  않는다(#876). 막기 전에 한 번 알려 주는 쪽이 기본이다.
- **영상 파일 저장·복사.** 주소·구간·메모만 저장한다(#792). 저작권 원칙과 데이터 주인 원칙
  모두에서 나온 경계다.
- **수치·상태 중심 화면.** 기록을 '할 일'로 만들지 않는다 — #888에서 운영센터의 사용 일지를
  상태 칩으로 거르지 않고 고객의 하루 기록으로 다루기로 정했다.
- **공개 기본값.** 새 기록을 몰래 공개하거나, 공개 여부와 발견 노출을 한 덩이로 다루지
  않는다(#425).
- **옛 세대 운영 규칙의 통째 승계.** 옛 문서는 참고 자료일 뿐이다. 과거의 공개 기본값·
  과금·인증 제공자·예시 데이터 구조를 자동으로 가져오지 않는다 — 이 원칙 문서도 옛 문구를
  옮긴 것이 아니라 4.1의 실제 결정에서 다시 썼다.
- **내부 정리가 먼저 되기.** 실제로 막히는 버튼·작성·감상·이동을 내부 코드 정리보다 먼저
  고친다(#884 — 첫 화면의 바닥 띠·숫자판·단추 색·궤도를 한 PR에서 손봤다).
