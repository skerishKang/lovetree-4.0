## 2026-11-01 Owner 확정 — 앞으로의 개발 기준은 4.1

- 첫 화면은 4.0의 SRC064·금테·카메라·'러브트리 · MEMORY ORBIT'를 재사용하고, 안쪽은 Limone Track32/59/58/56 원본 디자인과 현재 공통 메뉴/용어를 유지한다.

- PADIEM 공통 인증·COM2 기록 서버/DB·도메인 검증·동기화·소유권 계약은 재사용한다. 공통 src/server 수정은 가능하지만 두 UI의 데이터/ID/parentId/links/표지와 계정 격리 보존을 확인한다. 저장소 이름 lovetree-4.0은 그대로 쓴다.

## 2026-11-07 — 첫 트리 = 첫 여정 (A안: 어두운 무대)

- **새 트리 만들기는 첫 여정 화면 하나로 연다.** 로그아웃 첫 화면의 `처음 시작하기` → 로그인 뒤 트리가 0개인 계정, 첫 화면 가운데 `새 트리 만들기`(흰색 강조), 헤더 주 버튼 `새 트리 만들기`, 기존 작성 패널의 `새 트리` 탭, 둘러보기의 `내 기록 새로 시작`이 모두 같은 화면으로 간다. 이미 트리가 있는 계정의 새 트리도 같다.
- **오른쪽 패널은 순간 추가·이 순간 수정 전용이다.** 탭은 두 개뿐이고 새 트리는 첫 여정이 맡는다. 입력은 링크 또는 사진(파일은 고르면 바로 업로드) → 마음 한마디 → ‘더 적기’(제목·감정·날짜) 순서이고, 수정 모드에서 기존 값이 있으면 ‘더 적기’가 펼쳐진다. ‘내 기록 백업’과 ‘내 보관 파일·다시 첨부·삭제’는 계정 메뉴에서 연다. 저장 경로·미디어 메타데이터 규칙은 그대로다.
- 화면은 `public/v41/views/first-journey.html`이고 4.1 공통 헤더 아래 무대(iframe) 안에서 열린다. `reference/originals/first-journey.html`의 구성과 문구(첫 순간 심기 → 마음 남기기 → 첫 마음 카드가 피어났어요 → 다음 영상 잇기 → 첫 가지가 다정하게 이어졌어요)를 가져오되, 원본의 자체 머리글은 쓰지 않고 단계 표시(00~04)만 화면 안에 둔다.
- 단계: 00 트리 이름(좋아하는 대상, 필수) → 01 첫 순간(링크 또는 사진 주소, 마음 한마디 선택) → 02 마음 남기기(감정·기억할 시점·이유 선택) → “첫 마음 카드가 피어났어요” → 03 다음 영상 잇기(다음 링크·이어진 이유, `나중에 잇기`로 건너뜀) → “첫 가지가 다정하게 이어졌어요” → 04 성장 → `내 러브트리 보기`가 방금 만든 첫 순간의 기억책을 연다.
- 색은 `identity.css`의 `--lt-*` 토큰만 쓴다(무대 `--lt-stage`, 글자 `--lt-pearl`, 선 `--lt-gold-line`, 주 버튼 `--lt-rose`). 새 hex 없음. 글꼴은 Pretendard, 큰 제목은 첫 화면과 같은 650·-.055em, `word-break:keep-all`. 단계 전환은 transform이 아니라 페이드다. 390·360에서 모달·카드가 화면 밖으로 밀리지 않는다.
- **저장 계약은 바꾸지 않는다.** 02에서 `member.apply('new')` → 기존 `createTree`, 03에서 `member.apply('add')` → 기존 `addMoment`에 `parentId`=첫 순간, 연결 이유는 기존 `relation` 필드. 같은 workspace PUT·revision·도메인 검증을 그대로 지난다. 02의 “기억할 시점”은 기존 `date`, “이유”는 `note`(없으면 01의 마음 한마디)로 들어간다. 미디어 메타데이터는 #182·#183의 `validateMomentInput`/`normalizeMediaMetadata` 규칙을 그대로 따른다.
- 중간에 닫으면 입력을 `localStorage`에 try/catch로 보관하고 다시 열 때 “이어서 쓸까요?”를 묻는다. 이미 트리가 저장된 뒤 닫았다면 그 트리 id로 이어져 트리를 두 번 만들지 않는다. 화면은 서버를 직접 부르지 않고 셸에만 저장을 요청하며, 셸이 로그인·쓰기 가능을 확인한 뒤에만 저장한다(비로그인 서버 저장 없음).

## 중심

좋아하는 대상과의 순간을 남기고, 그 마음이 어떻게 이어졌는지 다시 보고 감상하는 팬 기록 서비스.

팬의 생각과 해석은 감정 기록 안에 포함한다. 공부·업무·범용 아이디어를 다루는 생각트리는 별도 서비스로 둔다. 초기에는 이전 저장소의 회원 자료 이전을 필수로 두지 않았지만, 현재 운영 계정과 서버 기록은 보존 대상이다. 이 초기 결정이나 4.1 채택을 DB 초기화·기존 기록 삭제 승인으로 해석하지 않는다.

## 핵심 경험

1. 첫 화면의 예시 순간을 눌러 감정과 연결을 이해한다.
2. 좋아하는 대상과 지금 남기고 싶은 순간을 적는다. 최초 입덕일을 요구하지 않는다.
3. 제목·마음·링크/첨부 중 하나로 첫 순간을 남긴다. 새 트리의 좋아하는 대상은 필수이며, 제목을 비우면 현재 규칙에 따라 표시 제목을 만든다.
4. 다음 순간을 추가하며 어디에서 이어졌는지와 선택적인 연결 이유를 남긴다.
5. 나중에 다시 열어 그때의 마음을 감상한다.

첫 성공은 화면 수가 아니라 **사용자가 첫 순간과 다음 순간을 연결하고, 저장 후 다시 열 수 있는 것**이다.

## 4.1 화면 용어 — 2026-10-31

기록 하나는 **순간**, 묶음은 **트리**, 트리 목록은 **내 책장**, 읽기는 **기억책**, 카드 보기는 **기억 보드**, 연결 구조는 **관계 지도**. 순간 사이의 관계는 **연결**, 그 설명은 **연결 이유**. 여러 순간을 따라가는 순서는 **경로**로 구분한다. 행동은 **첫 순간 남기기 / 새 트리 만들기 / 순간 추가 / 순간 수정 / 기억책 열기**. 예시 표시는 실제 예시에만 사용하며 사용자 제목·본문·데이터 ID는 용어 정리 대상으로 바꾸지 않는다.

## 4.1 시각 통일 기준 — 2026-10-31

서비스 이름은 한글 **러브트리**, 버전 **4.1**은 공통 로고 옆에 한 번 표시한다. 원본 화면 안에 별도 영문 서비스 로고를 반복하지 않는다. 화면명은 첫 화면 / 내 책장 / 기억책 / 기억 보드 / 관계 지도. 같은 트리의 보기 전환에서는 트리 제목·현재 보기·선택 순간을 공통 위치에 유지한다. UI는 자체 호스팅 Pretendard Variable, 책/순간 제목·기억책 감상 본문은 MaruBuri. 첫 화면의 SRC064 사진/금테/카메라 및 네 원본 화면의 구성·질감은 보존한다. 사용자 제목·본문·작품의 영어 제목은 번역하거나 치환하지 않는다.


## 4.1 시각 통일 기준 v2 — 2026-11-05 (대표 결정: 첫 화면이 디자인 원본)

첫 화면(SRC064)의 검은 무대·금테·진주 글자·유리 패널·알약 버튼이 러브트리 4.1의 디자인 원본이다. 안쪽 화면은 원본(Track32/59/58/56)의 종이·폴라로이드·코르크·책등·구성·질감을 보존하되, **무대와 강조색은 첫 화면 토큰을 따르고, 검은 무대 위 금테 카드 프레임 안에 놓인다**(첫 화면에서 카드를 가까이 본 것으로 읽히게).

- 토큰은 `public/v41/identity.css`의 `--lt-*` 한 곳에만 둔다. 새 UI의 색·모서리는 이 토큰만 쓴다. 원본 화면의 `:root` 색은 `identity.css`의 화면별 덮어쓰기로만 바꾸고, 원본 내부 구조·질감은 바꾸지 않는다. 새 hex를 흩뿌리지 않는다.

## 4.1 명시적 공유 범위 — 2026-11-01

기본은 비공개다. 소유자가 서버 미리보기에서 공개될 내용을 확인하고 링크 만들기를 눌러야만 추측하기 어려운 미등록 공유 주소가 생긴다. 이번 범위는 선택한 트리 한 개 전체이며, 트리 제목·대상과 그 트리의 모든 순간 제목·마음·감정·날짜·연결·외부 링크를 감상 전용으로 공개한다. 내 책장의 다른 트리, 계정/주체 식별자, 비공개 업로드 파일은 공개 응답에서 제외한다. 발견 목록·검색은 이 링크 공유와 자동으로 이어지지 않으며 #121에서 별도 명시 동의로 연결했다. 인기·추천 순위는 제공하지 않는다.

공개 읽기는 저장된 개인 workspace를 그대로 반환하지 않고, 매 요청마다 서버가 현재 소유 문서에서 허용된 트리 하나만 투영한다. 공유 취소가 성공하거나 트리가 삭제된 뒤에는 origin의 새 요청을 즉시 거부하고 모든 공유 응답을 no-store로 보낸다. 이미 방문자가 내려받거나 캡처한 사본은 원격으로 회수할 수 없다는 한계를 만들기·취소 화면에 알린다. 기존 LoveBud의 공개 기본값·비공개 과금·공개 순간 수 문턱은 승계하지 않는다.


## 4.1 발견·커뮤니티 범위 — 2026-11-01

공유 주소 생성과 발견 목록 공개는 서로 다른 동의다. 공유 주소를 만든 직후 `discoverable`은 거짓이며, 소유자가 해당 공유의 **발견에 공개**를 별도로 선택해야 검색·감정 필터·최신 공개 순 목록에 나타난다. 발견에서 내리면 미등록 공유 주소는 유지되고, 공유를 회수하거나 트리를 삭제하면 발견에서도 즉시 사라진다. 인기·추천 점수나 근거 없는 순위는 만들지 않는다.

즐겨찾기는 원본 공개 주소를 가리킬 뿐 원본 트리를 복제하거나 입양하지 않는다. **내 기록 새로 시작**도 대상 이름만 작성 흐름에 건네고 새 비공개 트리를 만들며, 원본 순간·ID·parentId·links를 복사하지 않는다. 즐겨찾기·공감·댓글·신고·차단은 개인 workspace JSON과 분리된 PostgreSQL 표에 저장한다. 쓰기는 로그인·제품 주체 확인, 중복 방지 키(댓글·신고), DB 유일 제약과 요청 빈도 제한을 적용한다.

신고 접수만으로 자동 숨김하지 않는다. 제품 관리자 화면에서 신고를 검토해 발견 목록 숨김 또는 복구를 명시적으로 선택하고 감사 로그를 남긴다. 관리자 댓글 숨김도 별도 감사 대상이다. 이 숨김은 커뮤니티 표시만 바꾸며 소유자 원본 기록을 수정·삭제하거나 공유 주소를 소유자 대신 회수하지 않는다. LoveBud의 공개 기본·과금·인기 모델은 승계하지 않았고, LoveBud의 안전 DTO·인증 쓰기·중복 방지 패턴과 Limone의 검색·감정 필터·읽기 전용 감상 흐름만 대조해 재사용했다.

## 4.1 첫 화면 카드 출처 — 2026-11-08 (대표 결정: 선명한 예시, 출처는 사용자가 고른다)

- **카드 메뉴 바깥 클릭**: shadow DOM 안 클릭은 document 리스너에서 host로 retarget돼 `target`만으로는 안쪽 클릭을 알 수 없다. 그래서 바깥 클릭 판정은 `composedPath()`로 하고, 경로가 없을 때만 `contains()`로 되돌아간다. 마우스로 메뉴를 열어도 즉시 닫히지 않고, 바깥 클릭·Esc로 닫힌다(키보드 ArrowDown 열림 유지).

## 4.1 내 책장 시각 기준 — 2026-11-08 (#212)

내 책장은 첫 화면과 같은 테마를 따른다(대표 결정 2026-11-08). **밤**은 어두운 무대·진주색 글자·금 포인트·Pretendard이고 장미색을 쓰지 않는다("한 권의 책" 강조는 진주 계열 흐린 톤). **정원**은 지금 크림색 책장과 글꼴을 그대로 둔다. 기억책·기억 보드·관계 지도는 계속 밤(A)이다.

- 책 카드는 표지에 트리 이름을 한 번만 쓰고, 표지 아래는 `순간 N개 · 마지막 YYYY-MM-DD` 하나만 둔다. `책 · 02`, `기본 표지` 같은 내부 표시는 두지 않는다. 선택 카드는 표지가 잘리지 않아야 한다.
- 표지 색은 `identity.css`의 `--lt-cover-1..4`에만 둔다(밤은 보드·지도 구분색, 정원은 기존 표지 색).
- 오른쪽 위 그림은 예시 책이 아니라 **실제 내 책**을 보여 준다. 책이 없으면 빈 무대만 남기고 안내 글자를 그림 위에 겹치지 않는다.
- **트리 이름 자동 접미사**: 트리를 만들 때 제목에 `, 나의 순간들`을 붙이지 않는다. 옛 데이터의 표시는 `public/v41/tree-name.{mjs,js}`의 `displayTreeTitle`이 자동 문구와 정확히 일치할 때만 접미사를 뗀다(저장 데이터 불변). 2026-11-08 기준 **내 책장과 기억책(track59 두 벌 화면)에 연결**했고, 셸 헤더(`트리: <이름>`·`#context-tree`·탭 이름)만 #213에서 연결한다. 기억책 안에서 트리 이름이 들어가는 자리는 책 상단 이름표와 책 목록 데이터 두 곳이다.
