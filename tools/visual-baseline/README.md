# visual-baseline — 리팩터링 전후 화면 비교 (#231)

```bash
node tools/visual-baseline/visual-baseline.mjs capture --out /mnt/e/base-before           # 로그아웃 예시 모드 28장
node tools/visual-baseline/visual-baseline.mjs compare --before /mnt/e/base-before --after /mnt/e/base-after   # 차이 % 표 + diff-*.png
```

- 기준치: 기본 0.1%, **기억 보드(board)만 0.5%** — 실·핀 선을 매 로드마다 미세하게 다시 그리고, 기울어진 사진 카드 테두리의 계단 현상으로 0.309%가 나온 사례가 있다(정리는 리팩터링 3단계 예정).
- `--base`(기본 `https://lovetree-4-0.pages.dev/v41/`)로 로컬 미리보기(`http://127.0.0.1:5173/v41/index.html` — vite는 `/v41/`만으로는 셸을 주지 않음)도 찍는다. `--threshold`(기본 0.1%)를 넘으면 종료 코드 1.
- 같은 조건에서 흔들리지 않게: 테마 고정·`Math.random` 고정 씨앗·CSS 애니메이션 일시정지·rAF 중단·토스트 숨김 + 두 번 연속 같은 그림일 때만 저장.
- 화면 도착 판정은 **보이는(#view·#view-next 중 hidden 아님) iframe의 주소**로 한다. Pages는 `.html` 없이 응답하므로 기대 이름도 확장자 없이 맞춘다. 셸 문서의 rAF·타이머는 건드리지 않고, 고정 장치는 화면이 다 열린 뒤 iframe 안쪽에만 건다(셸 화면 교체가 rAF 2회를 기다리기 때문).
- 기준선은 **5화면(첫 화면·내 책장·기억책·기억 보드·관계 지도) × 1440·390 × 밤·정원 = 20장 + 헤더 계정 자리 4장 = 24장**이다.
- **첫 여정은 로그아웃 기준선에서 뺐다**: `#journey/00`은 소유한 트리가 있어야 열리고(`shell.mjs`의 `session.snapshot().owned`), 로그아웃에서 열리지 않는 것이 의도된 동작이다. 로그인 상태 여정은 `tools/postdeploy --auto-login`이 확인한다.
- 장마다 **새 context·새 페이지**로 연다(크기·테마는 context 생성 시 고정). 도착 판정은 보이는 iframe의 주소가 기대 파일을 포함하고 `readyState==='complete'`일 때까지 200ms 간격으로 최대 8초 확인한다.
- 화면 교체 애니메이션이 소수점 배율로 남으면 픽셀이 흔들리므로, 다 열린 뒤 iframe 배율·투명도를 1로 고정하고 애니메이션은 0초가 아니라 **끝 상태**로 마무리한다(셸의 rAF·타이머는 그대로 둔다).
- 남은 흔들림: 기억 보드 1440(실·핀 영역에서 최대 0.15%), 390 아래쪽 카드 일부(0.01~0.07%). 같은 화면인데도 매 실행 미세하게 다시 그려진다.
- 크로미움은 `CHROME_PATH` → `~/.cache/ms-playwright/chromium-*` 순으로 찾고, playwright-core는 `tools/postdeploy/node_modules` 것을 재사용한다(새 의존성 없음).

## 알려진 의도된 차이: shelf 4장 (1.5단계 ④, #231)
`shelf-*` 4장은 2026-11 예시 판본·실제 기록 판본 통일(#231 ④)로 **4.9~9.0%** 차이가 난다. 고정 팔레트→테마 표지 색, 장식 책 4권→실제 예시 책, 카드 정보 줄·표지 사진·펼침 라벨 문구가 바뀐 결과이며 레이아웃 깨짐은 없다. ⑥단계(셸 경로 정리) 후 기준 스크린샷을 새로 뜨면 0.1% 기준으로 돌아간다.

## #1585 미리보기 공개 API 503에 영향받지 않는 기준 사진

비교 기준은 저장소의 영구 PNG가 아니다. 미리보기 검사에서 `merge-base` 배포본(없으면 운영 대체)을 `before`, PR 미리보기를 `after`로 **매번 새로 캡처**해 만든다. 두 번 모두 같은 버전의 `tools/visual-baseline/visual-baseline.mjs capture`를 사용한다.

캡처 브라우저는 `public-api-stub.mjs`의 고정 시험 응답을 같은 출처의 **GET 공개 API**에만 돌려준다. 숫자판의 `/api/community/stats`는 `{trees:17,moments:42}`이고, 공개 트리 목록·공개 순간 목록·꼬리표 순간 목록·인기 무대 목록은 항상 같은 시험 값이다. 쿼리나 실제 서버 상태와 무관하다. POST·PATCH·DELETE, 로그인/계정 API, 다른 출처 및 지정되지 않은 경로는 그대로 둔다.

이 방식은 **비교용 브라우저에만** 적용된다. 운영 서비스·미리보기 배포 설정·Cloudflare Functions·저장소 연결에 영향을 주지 않으며, `preview-gate.mjs`의 503 분류도 그대로다.

기준 사진을 다시 만드는 방법:

1. 현재 코드에서 `npm ci`, `npm run build`로 비교 도구와 화면을 준비한다.
2. 다음 캡처 두 명령을 같은 버전의 도구로 실행한다. `--base`에 기준 배포본과 PR 미리보기 URL을 각각 전달한다.
3. `compare`를 실행해 기준 초과 건수와 diff 이미지를 확인한다. `manifest.json`에는 각 사진의 `apiStubs` 경로가 기록된다.

```sh
node tools/visual-baseline/visual-baseline.mjs capture --base "https://기준배포주소/v41/" --out visual-before
node tools/visual-baseline/visual-baseline.mjs capture --base "https://미리보기주소/v41/" --out visual-after
node tools/visual-baseline/visual-baseline.mjs compare --before visual-before --after visual-after --out visual-diff --json visual-diff.json
```

워크플로는 원래 두 캡처를 동시에 수행하며, 변경할 필요가 없다. 차이율의 기본 기준 **0.1%**, 보드 기준 **0.5%**도 유지한다. 실제 화면이 바뀌면 비교 알림은 계속 발생한다. 기준 URL이 운영 대체인 경우 운영의 실제 화면 코드 차이는 별도 근거로 구분한다.

### 촬영 시각에 따른 궤도 카드 흔들림 제거

공개 숫자를 고정해도 첫 화면의 궤도·리본 카드가 서로 다른 순간에 그려지면 동일한 코드에서 큰 픽셀 차이가 생긴다. 비교 도구는 **보이는 내부 프레임에서만** 기존 시험용 궤도 훅의 `hold(true)`·`seek(0.25)`·`pauseFloat()`를 사용해 항상 같은 위상을 찍는다. 실제 사용자 화면이나 애니메이션 동작은 바꾸지 않는다. 이 보정은 픽셀 차이율을 무시하거나 알림 임계값을 올리는 방식이 아니므로, 실제 CSS·배치 변화는 그대로 검출한다.

- #1603과 #1604의 홈 1440 밤은 수정 전과 수정 후 PNG의 SHA가 서로 정확히 같아 두 PR이 각자 만든 새로운 변경이 아니다.

### 촬영 전용 보정

`capture-stability.mjs`를 통해 문서와 그림자 DOM의 CSS 애니메이션 및 Web Animations를 정지한다. 책 표지에는 **촬영 브라우저에만** `will-change:auto`·`transform-style:flat`을 적용해 3D 합성 계층의 비결정적인 픽셀 차이를 제거한다. 표지 사진·색·크기·좌표·내용은 숨기거나 바꾸지 않는다. 궤도 사진은 기존 시험용 훅으로 `pauseFloat`·`hold`·`seek(0.25)`·`syncDomPoses` 순서로 같은 위상을 유지한다.

제품 코드·배포 설정·`.github/`·운영 API 연결·비교 임계값은 변경하지 않는다.
